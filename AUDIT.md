# Audit — feature/ui-refresh (2026-10-28)

Scope: `public/generate.html`, `public/index.html`, `public/auth.html`, `public/admin-console.html`, `public/ui.css`, `public/app.js`, `public/admin.js`, `main.py`, `make.py`.

## Bugs

1. **main.py:1525** — Render subprocess has no timeout. With one executor worker (`main.py:102`) and `GENERATION_LOCK`, a single hung ffmpeg run or audio download blocks every user's queue forever. **Fix:** `subprocess.run(..., timeout=900)`, catch `TimeoutExpired`, and mark the job failed. **High** **Done — `_run_render` kills the whole process tree on timeout (`RENDER_TIMEOUT_SECONDS`, default 900s per reel); job marked failed and queue freed.**
2. **main.py:1031 / make.py:913** — `/api/estimate` downloads uncached ayah audio from everyayah synchronously inside the request (3 retries × 60s timeout per ayah), and the ayah range is unbounded (e.g. `2:1-286`). This ties up the threadpool and can hang requests for minutes. `/api/generate` has the same unbounded range (`main.py:1394`). **Fix:** cap `end - start` (e.g. 50), return 409 "measuring…" for uncached ayahs, or cap the download count per request. **High** **Done — max 50 ayat per request on estimate and generate (`MAX_AYAHS_PER_REQUEST`).**
3. **main.py:1296** — The admin audio upload invalidates the cached duration only for the default reciter. `fetch_ayah` (make.py:441) applies the custom audio for every reciter, so other reciters keep stale durations and the timing goes wrong. **Fix:** invalidate the key for every reciter of that language. **Med** **Done — `invalidate_ayah_duration(..., all_reciters=True)`.**
4. **make.py:76 (`DURATION_CACHE_FILE`)** — Runtime duration cache is written into tracked `data/ayah_durations.json`. This dirties git (that's the current uncommitted change). `data/` isn't volume-mounted in `rebuild.ps1`, so measurements are lost on every rebuild. **Fix:** move it to `CACHE_DIR/ayah_durations.json` and seed from `data/` on first read. **Med** **Done — cache now `cache/ayah_durations.json` (gitignored), seeded read-only from `data/`.**
5. **main.py:1041** — `plan_duration` raises `ValueError` (bad surah/range, unknown reciter), but only `OSError/RuntimeError/RequestException` are caught, so it returns 500. **Fix:** add `ValueError` → 400. **Med** **Done — `ValueError` → 400.**
6. **main.py:1014 (reported 400 for `shamshad_ali_khan`)** — Not reproducible on current code: `urdu_voice_id=shamshad_ali_khan` returns 200 in full and urdu_only modes, and `/api/reciters` IDs match `data/reciters.json` and the HTML defaults. A 400 only occurs if that ID is sent as `reciter_id` (wrong language) or if `length_limit < 30`. The likely cause was a stale container built before commit 4bef2d8. **Fix:** none needed. Optionally make the error name the offending ID. **Low**
7. **main.py:55** — `VIDEO_URL_SECRET` falls back to a random value per process, so signed video/zip links break after a restart and across multiple workers. **Fix:** require it at startup in production (diagnostics already reports it). **Low**
8. **main.py:101** — `GENERATION_JOBS` is in memory, so a restart loses job status and batch ZIP downloads. **Fix:** acceptable for now. Persist to `CACHE_DIR` if multi-instance is needed. **Low**
9. **main.py:476–489** — Ayah images are saved to `OUTPUT_DIR` and never cleaned up (`_cleanup_orphaned_output_files` only removes `.tmp/.part`). **Fix:** don't write locally when returning base64 (use a temp file), or add a cleanup for `ayah-image-*.png` older than 24h. **Low**

## Quran text / fonts

10. **make.py:987 + main.py:1229** — An admin `arabic_text` override replaces the verified KFGQPC Hafs text with free-typed Arabic and no validation. Hand-typed Quran text can reach rendered videos. **Fix:** remove the Arabic override (keep Urdu only), or accept it only if it matches `quran_qpc_hafs.json` after normalisation. **High** **Done — Arabic override removed from API, admin UI and renderer; Arabic always from SHA-256-verified `quran_qpc_hafs.json` (`make.verified_arabic_text`).**
11. **generate.html:176 / make.py:1022** — The "Arabic Ayaat" style element offers Amiri/Naskh/Nastaliq fonts, but make.py always uses the KFGQPC font, so the choice is silently ignored (correct for the Quran, misleading in the UI). **Fix:** disable the font select when the element is `arabic` or `bismillah`, and reject the `font` key for those in `validate_video_styles` (main.py:151). **Med** **Done — font select disabled for Arabic/Bismillah; server rejects a font for them.**
12. **make.py:1024** — The English translation font can be set to Nastaliq/Naskh (Urdu/Arabic fonts with poor Latin glyphs). **Fix:** restrict the `english` font to amiri_* or add a Latin font option. **Low**
13. **generate.html:10, index.html:11** — Amiri is still downloaded from Google Fonts, but `.arabic-font` was removed in the refresh and nothing uses it. **Fix:** drop Amiri from the font link. **Low**
14. **generate.html:76** — The Urdu helper text renders in the Inter fallback (system font), not a Nastaliq font. **Fix:** add `font-family: "Noto Nastaliq Urdu"` for `[lang="ur"]` in ui.css and load that font. **Low**

22. **app.js:506, 1047, 1050** — `alert()` is used for validation and clipboard feedback, which blocks the page and doesn't match the inline status UI. **Fix:** write to `#status-box` / a `role="status"` element. **Low**
23. **app.js:402, 418, 420** — Debug `console.log` calls in production. **Fix:** remove them. **Low**
24. **ui.css (global)** — The light theme works by overriding Tailwind dark classes with `!important`. ## Security

25. **generate.html:8,406; index.html:9,171; auth.html; admin-console.html:7,239** — `supabase-js@2` is loaded with a floating major version and no SRI, and the Tailwind Play CDN is used in production. A compromised or changed CDN script runs with access to user sessions. **Fix:** pin an exact version (`@supabase/supabase-js@2.x.y`) with `integrity=`, and build Tailwind to a static CSS file. **Med** **Done (partial) — supabase-js pinned to 2.45.4 with SRI; Tailwind pinned to 3.4.16 but no SRI (its CDN sends no CORS header). Static Tailwind build still open.**
26. **main.py:577 + app.js:394** — `GET /api/admin/music` is open to any signed-in user (shares a handler with `/api/music-list`). It's not harmful, but an `/admin/` path without the admin check is a trap for future changes. **Fix:** point app.js at `/api/music-list` and put `require_admin` on `/api/admin/music`. **Low**
27. **main.py:452** — `/api/generate-image` has no rate limit or premium check, and renders synchronously on the request thread, so any user can loop it to burn CPU. **Fix:** reuse the per-user "one active job" guard or a simple per-user cooldown. **Med** **Done — 10s per-user cooldown (429).**
28. **main.py:815** — `serve_signed_video` checks that the file exists before verifying the signature, so 404 vs 403 reveals which filenames exist. **Fix:** verify `exp/sig` first, then resolve the path. **Low**
29. **main.py:1538** — Job responses include a 7-day public Supabase signed URL per video, which outlives the app's 10-minute signed links. **Fix:** shorten `expiresIn` to around 1h, or omit `url` and use `/api/video-url`. **Low**
30. **main.py:1160, 1250** — Background and audio uploads are accepted on extension alone and then parsed by ffmpeg. They're admin-only, but the file contents are never checked. **Fix:** `ffprobe` the upload and reject anything that isn't the expected stream type. **Low**
31. **Auth coverage (checked)** — Every `/api/*` route except `health`, `reciters`, `video/{f}` and `batch-download/{id}` (both HMAC-signed) requires a user. Admin routes use `require_admin`. History, job and URL endpoints check ownership by `user["id"]`. The `next=` redirect in auth.js:12 is same-origin-checked, and verse/range/style/music inputs are validated. **Fix:** none. **Low**

## Performance

32. **make.py:217–226 + make.py:46** — In the normal profile both qualities encode with `libx264 -preset medium -crf 18 -tune film -threads 1`. "Balanced" only lowers the resolution, and single-threaded medium/CRF18 at 1080×1920 is the main cause of slow renders. **Fix:** per-quality settings, e.g. high: `-preset faster -crf 20`, balanced: `-preset veryfast -crf 23`, and `-threads 0` (or 2–4) unless `RENDER_MEMORY_PROFILE=low`. **High** **Done — preset per quality: fast=veryfast, balanced=fast, high=medium, CRF 18.**
33. **main.py:382 + app.js:622** — Every API call makes two Supabase round-trips (`/auth/v1/user` and `rpc/noor_my_access`), and job polling starts at a 2s interval, so a render costs hundreds of Supabase calls. **Fix:** cache `token → user` for around 60s (keyed by the token hash, bounded with `lru_cache` + expiry), or verify the JWT locally with the project's JWT secret. **Med** **Done — 60s token-hash auth cache (bounded at 1000).**
34. **main.py:1201, 1025–1026, make.py:896** — `quran.json` is parsed from disk on every `_validate_verse` call (twice per request) and again in `plan_duration`. **Fix:** load it once at module level (`functools.cache`). **Med** **Done — `quran.json` loaded once (`_quran_data`, `make.load_quran`).**
35. **main.py:1523** — `_prepare_ephemeral_media()` lists Supabase Storage (backgrounds, music, content/audio, 3 existence checks) before every render. **Fix:** run it at startup and after admin uploads only. **Med** **Done — runs once per process before the first render.**
36. **main.py:1698** — The batch ZIP is fully written to disk before streaming (up to 25 reels), which doubles disk use. **Fix:** acceptable at this size. Stream with `zipstream` if batches grow. **Low**
